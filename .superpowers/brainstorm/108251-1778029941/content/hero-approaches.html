Implementation Approaches

Three ways to build the Mystic Portal hero — each with different trade-offs

R

Recommended: Canvas 2D Particle System

A single <canvas> element behind the title. Pure JavaScript particle engine — no library. Renders 80-150 particles as glowing circles with additive blending. Vortex effect via polar coordinate math (particles orbit a center point with inward drift). Subtle parallax via mouse/gyroscope shifting the vortex center.

Pros
  • Zero dependencies — ~200 lines of vanilla JS
  • GPU-accelerated on all browsers via Canvas 2D
  • Easy to tune particle count based on device performance
  • Smallest bundle impact (~3-4KB gzipped)
  • No WebGL context limits or compatibility issues
Cons
  • No true 3D depth — simulated via size/opacity/speed layers
  • Additive blending needs compositing tricks for best glow
B

WebGL / Three.js

Full 3D scene with Three.js. Real depth, perspective camera, point sprites with custom shaders for glow. Vortex geometry with volumetric fog effect. Mouse/gyroscope controls the camera subtly.

Pros
  • True 3D depth and perspective
  • Most visually impressive — shader-based glow, bloom
  • Smooth parallax with real camera movement
Cons
  • Three.js adds ~150KB to bundle (even tree-shaken)
  • WebGL context can conflict with other GPU-heavy pages
  • More complex to maintain
  • Overkill for a hero banner that scrolls off screen
C

CSS + Minimal Canvas Hybrid

CSS handles the vortex (animated radial gradients with rotation transforms). A tiny Canvas overlay adds 30-50 floating particles. The "3D" comes from CSS perspective transforms on layered gradient rings.

Pros
  • Smallest JS footprint (~1-2KB)
  • CSS animations are extremely battery-efficient
  • Graceful degradation — works without JS at all
Cons
  • Limited particle count and behavior
  • 3D effect is the least convincing of the three
  • Parallax response harder to make smooth with CSS-only vortex
